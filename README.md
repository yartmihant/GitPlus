# GitPlus

Небольшой устанавливаемый CLI‑инструмент для автоматизации типового цикла коммита в Git‑репозитории:

- добавление всех изменённых и новых файлов в индекс;
- автоматическое управление версией в файле `VERSION`;
- формирование сообщения коммита (из аргументов или из `CHANGELOG.md`);
- создание коммита одной командой.

## Как это работает

Скрипт `gitplus.py` автоматически определяет один из двух сценариев работы:

Перед выполнением сценария скрипт проверяет рабочее дерево и индекс. Если изменений нет, он завершает работу без коммита и без обновления `VERSION`. В существующем репозитории изменение одного только `VERSION` также не считается основанием для коммита: это предотвращает повторный инкремент версии, оставшейся изменённой после предыдущего незавершённого запуска или слияния.

### Сценарий (a): Быстрый коммит (Fallback)

Этот сценарий запускается, если:
- Передан аргумент командной строки с текстом сообщения.
- Либо файл `CHANGELOG.md` отсутствует, поврежден или не содержит блока `[Unreleased]`.

**Действия:**
1. Инкрементирует версию в файле `VERSION`.
2. Формирует коммит с сообщением вида:
   ```text
   1.2.3 [2025-02-10 14:50:46]: сообщение из аргумента
   ```

### Сценарий (b): Коммит через Changelog

Этот сценарий запускается, если файл `CHANGELOG.md` существует и содержит заголовок с меткой `[Unreleased]`.

**Действия:**
1. Парсит `CHANGELOG.md`, находя блок изменений, помеченный как `[Unreleased]`.
   Пример заголовка: `## 1.2.3 [2025-02-10 14:50:46] [Unreleased]`
2. Извлекает версию из заголовка и обновляет файл `VERSION` (перезаписывает его значением из лога).
3. Формирует сообщение коммита из текста под заголовком (до следующего заголовка).
4. Удаляет метку `[Unreleased]` из `CHANGELOG.md`, фиксируя изменения.

## Требования

- Python 3.7+ (рекомендуется актуальная 3.x);
- установленный `git`;
- библиотека `GitPython`.

## Установка

Из каталога исходников установите пакет в выбранную Python-среду:

```bash
python -m pip install .
```

Установка автоматически подтянет `GitPython` и создаст две равнозначные команды — `gitplus` и `git+`. Обе вызывают функцию `main()` из установленного модуля `gitplus.py`; shell aliases и путь к исходному скрипту больше не нужны. Каталог исполняемых файлов Python-среды должен находиться в `PATH`.

При сборке `setuptools` может вывести предупреждение, что имя `git+` не соответствует рекомендуемому шаблону имён. Это предупреждение не мешает созданию и установке команды.

Для установки в глобальную Python-среду используйте её интерпретатор вне виртуального окружения. Если системный Python управляется ОС и запрещает установку через `pip`, можно установить CLI через `pipx` (при наличии установленного `pipx`):

```bash
pipx install .
pipx ensurepath
```

`pipx` хранит зависимости в отдельном окружении и делает обе команды доступными пользователю из любого каталога. После изменения `PATH` откройте новый терминал.

Удалите старые определения aliases `gitplus` и `git+` из конфигурации оболочки и откройте новый терминал, чтобы они не перекрывали установленные команды.

После обновления исходников переустановите пакет командой `python -m pip install --upgrade .` (для установки через `pipx` — `pipx reinstall gitplus`). Версия пакета при сборке читается из `VERSION`; `setuptools` используется только для сборки. При обычной установке исходный каталог после установки не требуется.

Прямой запуск `python /путь/к/gitplus.py` также сохраняется; для него установите зависимость в используемую Python-среду:

```bash
python -m pip install GitPython
```

## Использование

Запускайте `gitplus` или `git+` **из любой вложенной директории** внутри репозитория.
Скрипт поднимается по дереву каталогов до корня Git-репозитория, после чего работает с `VERSION`, `CHANGELOG.md` и изменениями всего репозитория.

### Вариант 1: Прямой коммит (Сценарий A)

Просто передайте сообщение коммита в аргументе:

```bash
gitplus "Исправил обработку ошибок"
```

### Вариант 2: Через Changelog (Сценарий B)

1. Отредактируйте `CHANGELOG.md`, добавив новый блок версии с меткой `[Unreleased]`.
   
   ```markdown
   ## 1.2.4 [2025-02-10 15:00:00] [Unreleased]
   
   ### Исправлено
   * Критическая ошибка в модуле X
   ```

2. Запустите скрипт без аргументов:

   ```bash
   git+
   ```

Скрипт автоматически найдет блок `[Unreleased]`, закоммитит изменения с этим текстом и обновит версию.
